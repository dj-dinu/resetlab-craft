# Analyzer release gates

Spectracraft is the first tool under the selected ResetLab Craft parent brand. The manager remains on hold. Work stays local until the product qualifies; no public repository, release, paid service or Instagram campaign has been created.

## Current local implementation

- One canonical full-spectrum engine supports MP3, WAV, AIFF, FLAC, AAC and ALAC, with actual codec/container checks and unchanged grading mathematics.
- A native desktop shell and token-protected loopback browser fallback share the same read-only interface. Native folder/report-save bridges are implemented.
- Inventory is asynchronous/cancellable and bounded; analysis is limited to 50 selected tracks per run.
- Measured grades, existing labels and ungraded errors are distinct. Near-boundary precision and intentional-bandwidth context are visible.
- Spectrum/time evidence is bounded and aligned to canonical bin timing; graph pooling never grades audio.
- Public JSON/native report saves remove machine-specific/cache paths and free-form local diagnostics.
- Spectracraft branding, a shared R signal SVG/native icon, a locally saved sun/moon appearance button and the Smooth scrolling preset are implemented. The separate appearance/scrolling dropdowns are removed; grade filters remain. Discrete wheel smoothing preserves the real document scroll position; fine gestures, keyboard controls, forms and nested overflow retain native behavior, with automatic reduced-motion fallback.
- A private Windows bundle recipe generates and hashes the same canonical source; preliminary dependency notices do not settle redistribution requirements.

## Required before GitHub release

1. Finish actual desktop/bundle checks, including frozen worker execution, all claimed codecs, native dialogs, report saves, cancellation, app close and whole-file source hashes. The bundle is a local alpha until these pass.
2. Test a clean Windows machine without developer Python or DJ software; document actual prerequisites such as WebView2 and all bundled dependencies.
3. Build and execute native macOS packages on every advertised Intel/Apple Silicon architecture. No native macOS qualification has occurred on this Windows machine.
4. Qualify each advertised codec/profile/container/channel scope using the [format matrix](FORMAT_SUPPORT.md). Implementation bounds are not a blanket support claim.
5. Validate long/large/I/O workloads, peak memory/disk behavior, resource-limit errors and the implemented safe cache retention policy under storage pressure. New owned finished caches retain three jobs; legacy, active and unrecognized data are preserved.
6. Review the selected GPLv3-only source license/ownership and resolve dependency licenses, bundled binary inventories, notices, exact corresponding-source/build/relinking obligations and signing/distribution decisions.
7. Scrub private settings, canonical patch helpers, real music, artwork, private diagnostic caches and regression logs. Publish only reviewed source, synthetic/public fixtures and permitted dependencies.
8. Observe DJs/producers completing the simple workflow without coaching; confirm that they understand HQ/MQ/LQ as spectral coverage, inspect evidence and export useful findings.
9. Review and approve the concrete release contents and supported-platform claims. Then create GitHub assets and a public beta.
10. After release, create short Instagram demonstrations of verified shipped behavior, promoting both the app and the user's brand. Track downloads and relevant leads separately.

## Local limits to disclose

Analysis: 50 selected files. Inventory: 10,000 candidates / 100,000 visited entries, with incomplete-inventory warnings. Canonical processing: 24 hours / 172,800 bins per track, 250,000 batch report bins, 8–192 kHz and at most eight channels. These are bounds; only tested variants are qualified.

Retained spectrum evidence defaults to 32 MiB. Exceeding that evidence budget removes the graph with a reason while full grading continues. Processing/report limits are ungraded. Preview/report loading is also bounded. At most three completed jobs and three inventories remain in memory. New owned caches retain three finished analyses; active, legacy/unmarked and unexpected data remain preserved, so there is no blanket disk-byte cap.

No analyzer route renames, retags, moves, deletes or re-encodes music, and no DJ collection is edited. Public reports retain relative filenames while omitting machine-specific/cache paths; they are sanitized, not anonymous certificates.
